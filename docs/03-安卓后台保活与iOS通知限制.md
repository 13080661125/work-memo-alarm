# 03 · 安卓后台保活注意事项 & iOS 本地通知系统限制

> 这是整个项目最容易踩坑的地方。请先理解原理，再照着清单逐项配置。

---

# 一、本项目的闹钟是怎么"后台响"的（先说结论）

```
用户在 APP 里保存闹钟
        │
        ▼
NotificationService.scheduleAlarm()
        │
        ▼
向【操作系统】注册一条"定时通知"（Android: AlarmManager / iOS: UNUserNotificationCenter）
        │
        ▼
APP 退出、被杀、手机重启 —— 都不影响，因为闹钟已经交给系统托管
        │
        ▼
到点后由【系统】发出通知 → Android 可通过全屏意图直接拉起 APP 响铃页
```

**关键结论：闹钟响不响，取决于"系统是否愿意按时投递通知"，而不是 APP 是否还活着。**

因此本项目**刻意没有使用前台服务 / 长连接保活**，原因：
- 前台服务需要常驻通知栏，耗电、用户反感；
- 国产 ROM 会主动查杀常驻服务，反而更不稳定；
- 系统级 AlarmManager 的可靠性远高于普通进程保活。

# 二、Android 后台保活注意事项

## 2.1 必须拿到的三个"开关"

| 项目 | 不开启的后果 | 本项目处理 |
| --- | --- | --- |
| **通知权限**（Android 13+） | 通知完全不弹，等于闹钟不响 | 启动引导自动申请 `POST_NOTIFICATIONS` |
| **精确闹钟权限**（Android 12+） | 系统只允许"不精确"闹钟，可能延迟 5~15 分钟 | 启动引导跳转系统「闹钟和提醒」页 |
| **电池优化白名单** | 息屏一段时间后进程被冻结，通知被延迟/丢弃 | 启动引导申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` |

对应代码：`lib/services/permission_service.dart` + `HomePage._guidePermissions()`
用户可随时在 **设置页** 查看这三项状态并重新开启。

## 2.2 已做的系统级适配（代码 / 配置层面）

| 措施 | 位置 | 作用 |
| --- | --- | --- |
| `AndroidScheduleMode.exactAllowWhileIdle` | `notification_service.dart` | 允许在 **Doze 低电耗模式**下精确触发 |
| `RECEIVE_BOOT_COMPLETED` + `ScheduledNotificationBootReceiver` | `AndroidManifest.xml` | **手机重启后自动恢复闹钟** |
| `fullScreenIntent: true` + `USE_FULL_SCREEN_INTENT` | 通知详情 + Manifest | 锁屏时直接弹出响铃页 |
| `showWhenLocked / turnScreenOn` | `MainActivity.kt` | 锁屏显示并点亮屏幕 |
| `AndroidNotificationCategory.alarm` | 通知详情 | 让系统按"闹钟"优先级处理 |
| 启动即重新注册全部通知 | `AlarmProvider.load()` | 换机、清缓存后自动恢复 |
| 设置页"重新注册全部闹钟" | `SettingsPage` | 手动兜底修复 |

## 2.3 国产 ROM 需要用户手动设置（务必写进用户引导）

即便权限都开了，小米 / 华为 / OPPO / vivo 等厂商仍可能拦截。请在设置页提示用户：

| 品牌 | 设置路径（大致，随系统版本略有差异） |
| --- | --- |
| **华为 / 荣耀** | 设置 → 应用 → 应用启动管理 → 找到本应用 → 关闭"自动管理"，勾选"允许自启动""允许后台活动"；手机管家 → 电池 → 关闭"省电模式" |
| **小米 / Redmi** | 设置 → 应用设置 → 应用管理 → 本应用 → 自启动（开）；省电策略 → 选择"无限制"；神隐模式 → 关闭 |
| **OPPO / 一加** | 设置 → 应用 → 应用管理 → 本应用 → 允许后台运行（开）；电池 → 应用速冻 → 关闭 |
| **vivo / iQOO** | 设置 → 电池 → 后台高耗电 → 允许本应用；i 管家 → 应用管理 → 自启动（开） |
| **三星** | 设置 → 电池 → 后台使用限制 → 将本应用加入"永不休眠的应用" |
| **魅族** | 设置 → 应用管理 → 本应用 → 后台管理 → 允许后台运行 |

> 建议在 APP 首次启动时，用一张图文弹窗说明"为保证闹钟准时，请完成以下设置"，
> 并提供"打开系统设置"按钮（`PermissionService.openSystemSettings()`）。

## 2.4 不要做的事（反面清单）

- ❌ 不要启动常驻前台服务"保活"——耗电且国产 ROM 照样杀；
- ❌ 不要用 `Handler` / `Timer` 在 Dart 层自己算时间——APP 被杀就全失效；
- ❌ 不要降低 `targetSdk` 来绕过权限——Google Play 有最低版本要求；
- ❌ 不要频繁重建通知渠道——渠道属性（声音/震动）只在首次创建时生效，反复改无效。

## 2.5 测试与排查命令

```bash
# 查看系统里已注册的闹钟（确认是否真的注册成功）
adb shell dumpsys alarm | grep -A 3 work_memo_alarm

# 模拟 Doze 模式，验证低电耗下闹钟是否还能响
adb shell dumpsys deviceidle force-idle
adb shell dumpsys deviceidle step      # 多次执行直到状态变为 IDLE

# 查看通知是否被系统拦截
adb shell dumpsys notification --noredact | grep work_memo_alarm

# 查看是否被电池优化限制
adb shell dumpsys deviceidle whitelist
```

**真机测试标准流程**：
1. 新建闹钟，时间设为 1~2 分钟后；
2. 按返回键（**不杀进程**）退回桌面 → 等待 → 应按时响；
3. 从最近任务划掉 APP（**杀进程**）→ 等待 → 应按时响；
4. 锁屏 → 等待 → Android 应直接弹出响铃页；
5. 重启手机 → 等待 → 应按时响（验证开机恢复）。

# 三、iOS 本地通知的系统限制（重要）

## 3.1 核心限制：iOS 没有"后台闹钟"概念

| 能力 | Android | iOS |
| --- | --- | --- |
| APP 在后台主动执行代码 | 可以（受限制） | **不可以**（除后台刷新、音频、定位等特定场景） |
| 到点直接弹出 APP 自定义全屏界面 | 可以（fullScreenIntent） | **不可以** |
| 到点发出系统通知 | 可以 | 可以（唯一可靠方式） |
| 通知声音 | 可自定义铃声 | 可自定义（文件必须在主 bundle，<30 秒） |
| 锁屏显示 | 可以 | 可以 |

**因此在 iOS 上：**
- 闹钟到点 → 系统弹出**系统通知**（横幅 / 锁屏 / 通知中心），播放通知声音（约 1 次，不会持续循环）；
- 用户**点击通知** → APP 被唤醒 → 显示全屏响铃页 → 开始持续铃声 + 震动；
- 用户点通知上的"贪睡"→ APP 被唤醒 → 在 Dart 层注册 10 分钟后的新通知。

> 也就是说：**iOS 上"响一声就停"是系统行为，不是 Bug。**
> 想持续响，必须等用户点击通知进入 APP（本项目已这样实现）。

## 3.2 具体限制清单

| 限制 | 说明 | 应对 |
| --- | --- | --- |
| **最多 64 个待触发通知** | `UNUserNotificationCenter` 最多保留 64 条 pending 通知，超出的会被**静默丢弃** | 本项目每个重复闹钟按"星期"注册，最多 7 条 → 建议**不超过 9 个重复闹钟**；或改为"只注册最近一次"的动态调度方案 |
| 通知声音必须 < 30 秒 | 超过会被系统替换为默认音 | 本项目铃声最长 4.3 秒，符合要求 |
| 声音文件必须在主 bundle 根目录 | 无法访问 `flutter_assets` | 已在部署文档要求加入 Copy Bundle Resources |
| 静音开关打开时 | 默认不播放 | 本项目 `AudioContextConfig(respectSilence: false)`，使 iOS 静音时也播放 |
| 专注模式 / 免打扰 | 普通通知会被静音 | 已设置 `interruptionLevel: .timeSensitive`（iOS 15+），可穿透专注模式 |
| 前台收通知默认不显示 | 需设置 `UNUserNotificationCenter.delegate` | 已在 `AppDelegate.swift` 中配置 |
| 模拟器无法测试通知推送 | 真机才行 | 必须用 iPhone 真机测试 |
| 用户拒绝通知权限后 | APP 内无法再次弹窗 | 只能引导去系统设置（设置页已提供入口） |
| 通知时间精度 | 本地通知精度到秒，但系统可能因省电略延迟 | 与安卓一致，接受系统调度 |

## 3.3 iOS 端"闹钟不响"排查清单

1. 真机测试？模拟器不会弹通知。
2. 首次启动时点了"允许"通知？设置 → 通知 → 本应用 → 允许通知。
3. 手机是否处于"专注模式/睡眠模式"？已用 timeSensitive 缓解，但"睡眠"模式仍可能屏蔽。
4. wav 文件是否加入了 **Copy Bundle Resources**？（只影响声音，不影响弹窗）
5. 是否超过 64 条待触发通知？删掉几个闹钟试试。
6. 系统时间是否正确？时区变化后需要重新注册（本项目启动时会重新注册全部）。

# 四、双端对比速查表

| 项目 | Android | iOS |
| --- | --- | --- |
| 后台机制 | AlarmManager（系统托管） | UNUserNotificationCenter（系统托管） |
| APP 被杀后是否响 | ✅ 会 | ✅ 会（系统发通知） |
| 重启后是否响 | ✅ 会（需 RECEIVE_BOOT_COMPLETED） | ✅ 会 |
| 锁屏自动弹 APP 页面 | ✅ 会（全屏意图） | ❌ 不会（只能弹系统通知） |
| 持续响铃 | ✅ 进入 APP 后持续播放 | ✅ 进入 APP 后持续播放 |
| 通知操作按钮 | ✅ | ✅（需 iOS 10+，已配置分类） |
| 自定义铃声 | ✅ res/raw | ✅ 主 bundle，<30s |
| 数量上限 | 无明确限制 | **64 条 pending** |
| 需用户手动开权限 | 通知 / 精确闹钟 / 电池白名单 | 仅通知权限 |

# 五、给用户的产品建议（提升到达率）

1. **首次启动引导**：用一页图文说明"为什么要开这些权限"，比直接弹系统弹窗转化率高得多；
2. **设置页常驻自检**：本项目已实现，用户随时能确认三项状态；
3. **重要提醒用"重复"**：重复闹钟比一次性闹钟更难被系统漏掉；
4. **关键事项双保险**：对极重要的提醒，可同时设置提前 10 分钟的第二个闹钟。
